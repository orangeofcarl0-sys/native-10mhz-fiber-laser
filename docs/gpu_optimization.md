# GPU 计算路径改造：模型对应、验证与限制

## 对附件建议的核对

附件的频谱传递、CNT 前缀扫描、EDF 融合方向成立，但部分代码事实属于旧版本：

| 项目 | 本轮开始时（801fd03） | 本轮实现 |
|---|---|---|
| EDF 单元变换 | 已从6次降为4次，15单元共60次 | 跨单元直接传递频谱，非线性处才转换 |
| 无源段 | 41个 Kerr 步、五个段，共92次 | 段间传递频谱，保留各段旋转次序 |
| 每圈变换数 | 152，不是182 | 时域兼容接口116；纯频域返回映射114 |
| 常驻状态 | 已有时域常驻，但圈末重新FFT诊断 | 跨圈频域常驻；复用频谱诊断；圈末时域检查额外1次IFFT，共115 |
| CNT同步 | 上轮已去掉Python设备标量assert | 继续设备失败标记；增加融合块内扫描 |
| 扫描诊断 | 原scan仍每圈取回完整场 | 新增独立scan_resident分块下载；旧scan保留精确SciPy语义 |

变换数指一次批量FFT/IFFT调用，不是单条变换数。64案例时每次调用处理128条偏振序列。
五个原始GDD切片均有56个 Kerr 步，但修改空间步长后必须重新计数。

## 离散映射为什么保持不变

`spectral_engine.py` 保存未归一化前向频谱 F。每个 Kerr 前做 IFFT、Kerr 后做 FFT。
线性半步、段间Jones旋转、损耗之间直接传递频谱，去掉无物理操作隔开的 IFFT→FFT。
没有合并不同方向的矩阵次序，也没有更改 Strang 分裂或纵向增益更新。

特别保留旧模型的偏振约定：无源段 Kerr 在该段基底计算，EDF Kerr 在实验室基底计算。
回归测试使用非零段角、双折射、DGD和双偏振输入，而非只比较默认简化状态。
EDF 每单元输出加权频谱功率成为下一单元输入；同单元两个半步使用更新前的反转，
之后仅更新一次反转和泵浦。`gain_mode=frozen` 仍不更新反转。

## CNT 前缀算法

递推 q_next=a*q+b 的有序复合为 (a2*a1, a2*b1+b2)。每腔一个256线程块：
每线程先汇总连续采样片段，块内对仿射系数扫描，再从自己的入口q展开该片段。
共享内存扫描每层读写分离、同步，空片段使用恒等变换。没有除以极小累乘，避免下溢除零。
同一内核输出透射后的双偏振场、最终q、入射能量、峰值和最小吸收。
非法透射率输出NaN，由常驻路径标记失败并保留上一合格状态。

## EDF 与 Kerr 融合

三个EDF内核分别做频谱加权归约、增益半步、速率更新。
不构造整批gain/hh数组；gap/tau采用设备上逐单元最大值。
Kerr采用二维网格和原地写回，每线程只读写一个时刻的两个偏振，不存在跨线程依赖。
无源整步线性系数在初始化时预计算。全部FP64，未启用fast math。

## 公平计时

按 [CuPy性能文档](https://docs.cupy.dev/en/stable/user_guide/performance.html) 使用CUDA Event，
预热后交错随机顺序重复7次，保存每次样本与中位数，并记录同步后的主机墙钟时间。
比较同一物理状态、相同精度/批量/网格；每次计时包含设备输入副本，不包含编译与主机传输。
两种拓扑、2048/8192点、64案例都测试。CNT单独计时与整圈消融分开呈现。
Nsight CLI当前未找到，**这些不是Nsight逐kernel占比统计**；不能把部件计时直接相加，
也不能把理论FFT减少比例视作实际加速。

## 初筛与认证

`MAP_GPU=1` 的原扫描默认使用新的兼容核心，仍保留精确CPU诊断。
`scan_resident.scan` 固定64槽，避免每20圈收缩导致的FFT形状变化；代价是继续计算失效槽。
它的峰数只有局部极大值及10%阈值，不含prominence/平台峰规则；不能用于认证单脉冲。
边界仅在圈末检查，仍需CPU自适应回放与严格复核。失败原因不等于物理不可行。

没有宣称FP32可以安全淘汰候选，也没有把混沌/分岔附近的短程对照当成长程吸引态等价证明。
CUDA Graph、callbacks、自动bucket压缩及显式FFT plan仍未实施；先依据本轮整圈实测判断优先级。
